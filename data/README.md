# Customer Support on Twitter — Data Directory

## Dataset source

**Kaggle dataset**: [thoughtvector/customer-support-on-twitter](https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter)

The dataset contains ~2.8 million tweets exchanged between customers and brand
support accounts on Twitter between October–November 2017.

## Dataset schema (`twcs.csv`)

| Column | Type | Description |
|---|---|---|
| `tweet_id` | int64 | Unique tweet identifier (sequential integer, not a real Twitter ID) |
| `author_id` | str | Account that posted the tweet. Brands use real names (e.g. `AmazonHelp`); customers are anonymised numeric IDs |
| `inbound` | bool | `True` = customer tweet (directed *at* a brand); `False` = brand/support response |
| `created_at` | str | UTC timestamp in Twitter format `"Tue Oct 31 22:10:47 +0000 2017"` |
| `text` | str | Raw tweet text (includes `@mentions`) |
| `response_tweet_id` | str | ID(s) of the tweet(s) this tweet was replied *to* by a support agent (can be comma-separated multi-values) |
| `in_response_to_tweet_id` | str | ID of the parent tweet this tweet is replying to; used to walk the reply chain and reconstruct conversations |

### Key identifiers

- **Brand/company identifier**: `author_id` when `inbound == False`
- **Customer identifier**: `author_id` when `inbound == True` (anonymised numeric strings)
- **Conversation thread**: reconstructed by walking `in_response_to_tweet_id` up to the root tweet (see `profile.py`)
- **Reply relationship**: `in_response_to_tweet_id` → parent tweet; `response_tweet_id` → child tweet

## How to run the profiler

```bash
# From the repo root
python src/data/profile.py \
    --input  dataset_raw/twcs/twcs.csv \
    --output data/brand_profile.csv
```

The script will:
1. Discover all 108 brand accounts (outbound author IDs)
2. Load the full 2.8M-row CSV in 200k-row chunks
3. Reconstruct conversation threads via iterative reply-graph traversal
4. Compute per-brand quality metrics
5. Write results to `data/brand_profile.csv`

Approximate runtime: **3–6 minutes** on a modern laptop.

## Preprocessing assumptions

1. **Conversation reconstruction**: `in_response_to_tweet_id` is the primary link. When a cell
   contains a comma-separated list (e.g. `"5,7"`), only the **first** value is used as the
   direct parent. This is conservative but sufficient for conversation threading.

2. **Brand affiliation**: A conversation is attributed to the brand that **first replied**
   (first outbound tweet by `tweet_id` ordering). Conversations with no outbound tweet
   are excluded from all brand metrics.

3. **"Resolved" heuristic**: A conversation is considered resolved if the **last tweet**
   in the thread (by `tweet_id` order) is an outbound (brand) tweet. This is an approximation —
   the dataset has no explicit resolution label.

4. **Usable conversation**: A conversation that contains ≥1 inbound tweet AND ≥1 outbound tweet.

5. **Missing `in_response_to_tweet_id`**: Root tweets (conversation starters) naturally have
   `NaN` for this column. This is expected and not counted as a data quality issue.
